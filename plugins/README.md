# KeeWeb Next plugins

Plugins for the web app and the webview shell. The gallery in **Settings → Plugins**
loads `plugins.json` from this directory, so pointing `Links.Plugins` at this folder is
all the app needs.

Gallery URL: `https://raw.githubusercontent.com/yanqingwang/keeweb-next/master/plugins/plugins.json`

## Included plugins

These are JavaScript ports of ideas from the [KeePass plugin list](https://keepass.info/plugins.html),
kept small enough to stay readable:

| Plugin | KeePass counterpart | What it does |
| --- | --- | --- |
| `quick-search` | QuickSearch | `Ctrl+K` / `Ctrl+F` focuses the entry search field |
| `copy-hotkeys` | Quick Copy style entry shortcuts | `Alt+1..4` copy user, password, URL, title of the selected entry |
| `open-url` | URL tools | `Alt+Shift+U` opens the selected entry's URL in the system browser |
| `password-age` | Password Age | Marks list rows whose entry was last changed more than 1 or 2 years ago |
| `duplicate-finder` | Duplicate Entry Finder | `Ctrl+Alt+D` reports entries sharing a password or URL in the current view |

Not ported, and why: auto-type needs a native keyboard injector the webview shell does
not have; USB/YubiKey plugins need native modules and `ykman`; Windows-specific
(KeeAgent, DPAPI) plugins have no equivalent here.

## Signing

KeeWeb verifies every plugin resource and the gallery with RSASSA-PKCS1-v1_5 / SHA-256.
The shell trusts two keys; this fork's key is installed as
`app/resources/public-key-new.pem`, and the matching private key is
`signing/private-key.pem` (committed on purpose so the gallery can be regenerated by
anyone building this fork — do not reuse it for anything else).

Regenerate after editing a plugin:

```bash
node plugins/signing/sign.mjs
```

It rewrites each `manifest.json` with fresh resource signatures and a fresh
`plugins.json`. `sign.mjs` refuses to run if the app's second public key does not match
`signing/public-key.pem`.

## Installing without the gallery

Settings → Plugins accepts a URL to a plugin directory; any static server works:

```bash
python3 -m http.server 8000 --directory plugins
# then install http://127.0.0.1:8000/quick-search
```

Plugins are executed with the app's own modules available through `require`, so treat
them like any other code you run in the app.

The webview shell serves the app from `tauri://localhost`, a secure context, so plain
`http://` plugin URLs are blocked there as mixed content; use an `https://` URL or the
gallery. The browser build has no such restriction.
